# Prompt for Constructing a Winning Hackathon Project

You are a senior software engineer and hackathon judge with extensive experience in evaluating winning submissions. Your task is to create a comprehensive prompt that guides participants in developing a hackathon project that maximizes their chances of winning.

## Context

Hackathons typically last 24-48 hours with teams of 1-4 people working intensively to build innovative solutions. Judges evaluate submissions across multiple criteria including problem-solving, technical implementation, creativity, demo quality, and presentation.

## Objective

Create a prompt that helps hackathon participants design and build projects that achieve maximum impact with minimal resources, focusing on delivering compelling demonstrations that clearly show the value proposition.

## Prompt

```
You are tasked with building a winning hackathon project. Follow these guidelines to maximize your score:

### Phase 1: Problem Selection (30 minutes)
Choose a problem that is:
1. Specific and well-defined
2. Has measurable impact
3. Is solvable within the time constraints
4. Demonstrates clear before/after value

Ask yourself:
- Who experiences this problem?
- How often does it occur?
- What is the quantifiable cost/pain?
- Can I show a dramatic improvement?

### Phase 3: Architecture Planning (30 minutes)
Plan a robust architecture that:
1. Clearly separates concerns
2. Uses appropriate design patterns
3. Anticipates future extensions
4. Includes proper error handling and security

Essential Components:
- Clean API design (REST/gRPC)
- Database schema (if applicable)
- Security best practices
- Monitoring and logging strategy
- Deployment considerations

### Phase 4: Implementation Strategy (Remaining Time)
Prioritize ruthlessly:
1. Core functionality that solves the problem
2. Compelling demonstration scenarios
3. Polished user interface (even if minimal)
4. Documentation and setup instructions
5. Error handling and edge cases

Technical Excellence Requirements:
- Secure credential management (no hardcoded secrets)
- Proper input validation
- Graceful error handling
- Consistent code style and naming
- Meaningful commit messages and documentation

### Winning Patterns

1. **Start with Documentation First**
   - Write your README before coding
   - Define your API contracts early
   - Plan your demo scenarios in detail

2. **Build a Compelling Narrative**
   - "Before StockPulse, merchandisers spent hours on spreadsheets..."
   - "With StockPulse, recommendations appear automatically in 30 seconds..."

3. **Focus on the Magic Moment**
   - Identify the one feature that will wow judges
   - Make sure it works flawlessly
   - Build the entire demo around it

4. **Show Understanding of Production Concerns**
   - Security best practices
   - Error handling and recovery
   - Scalability considerations
   - Monitoring and observability

5. **Prepare for Deep-Dive Questions**
   - Architecture decisions
   - Trade-offs considered
   - Scaling approaches
   - Security measures

Remember: Judges see dozens of projects. Yours needs to stand out in the first 60 seconds.

## Execution Tips

When applying this prompt during a hackathon:

1. **Time Management**: Strictly adhere to phase time allocations
2. **Continuous Validation**: Regularly check if you're solving the right problem
3. **Documentation Discipline**: Keep README and comments updated as you build
4. **Demo Mindset**: Every feature should contribute to the final demonstration
5. **Quality Over Quantity**: Fewer features implemented excellently beat many half-baked features

Use this framework to maximize your chances of creating a winning hackathon submission that stands out for its technical excellence, problem impact, and compelling demonstration.
